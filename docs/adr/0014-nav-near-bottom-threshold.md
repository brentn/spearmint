# Bottom-nav near-bottom threshold, sized from live-measured height

The auto-hiding bottom nav's box-collapse animation (ADR 0012) changes `.app-scroll`'s own `clientHeight` mid-transition, which fed synthetic scroll events back into the direction-based hide/reveal logic and caused visible bouncing near the end of a page's content (GitHub issue #28). Fixed with a near-bottom margin in `computeNavHidden` symmetric to the existing near-top threshold: within that margin of the true scroll end, the nav is unconditionally shown, which is idempotent under noisy scroll events instead of toggling. The margin — and the matching `.app-content` bottom padding that keeps the revealed nav from covering the last item — are both driven by `NavShell`'s live-measured `offsetHeight` (via `ResizeObserver`, sampled only while visible) rather than a static constant, because unlike the existing max-height transition buffer (a cosmetic-only approximation), drift here would silently let content sit behind the nav again.
