# CategoryPicker replaced with a full-screen sheet, native `<select>` rejected again

The anchored popover (capped at 16rem/256px tall, positioned off the trigger's own rect) was hard to use once the taxonomy grew past ~48 entries: too little room to browse, and hard to scan even with the filter textbox. Reverting to a native `<select>` was reconsidered, since it also solves the "looks native" goal for free — but on-device comparison (iPhone, real category data) showed iOS renders a single-select as a fixed-height wheel that shows about as few rows as the old popover did, and it can't host a filter textbox at all, so it fixed neither actual complaint. `CategoryPicker` is now a near-full-screen custom sheet instead: same filter textbox as before, options flattened into a single alphabetized list with each child labeled `"Parent: Child"` (`buildCategoryOptions` in `category-grouping.util.ts`) rather than grouped under headers, dark floating-card styling with a native-picker-style slide-up/scale/fade open animation. Being a fixed full-screen overlay instead of an anchored popover also removes the whole class of positioning bugs the old popover had accumulated (issues #16, #22, #24) — nothing is anchored to a trigger that can scroll or resize out from under it anymore.

Three variants (current popover / native select / custom sheet) were built and compared live on an iPhone before deciding; that comparison harness is preserved on the `prototype/category-picker-variants` branch rather than in `main`.
